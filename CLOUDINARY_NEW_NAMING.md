# Загрузка на Cloudinary с новым неймингом (107 проектов, несколько медиа в одном)

## Суффиксы Cloudinary

При загрузке Cloudinary может добавлять к имени файла суффикс (например `98` → `98_gel9bi`). Пример URL иконки:

`https://res.cloudinary.com/dwwyducge/image/upload/v1770317040/98_gel9bi.png`

В таком случае в `portfolio_data.json` в полях `media.path` и `media.thumbnail` нужно использовать **реальный public_id** (с суффиксом), иначе медиа не откроются.

Два варианта:

1. **Файл маппинга** — создать в корне проекта `cloudinary_mapping.json` (по образцу `cloudinary_mapping.example.json`). Ключи — логические id (`98`, `9a`), значения — public_id на Cloudinary (`98_gel9bi`, `9a_abc12`). После этого снова запустить `python build_portfolio_from_folders.py`: скрипт подставит эти значения в path и thumbnail.
2. **Локальные имена с суффиксом** — если в папках `images/` и `icons/` файлы уже названы как на Cloudinary (например `98_gel9bi.png`), скрипт сам подставит это имя в URL.

## Структура файлов

- **icons/** — 107 иконок для доски (по одной на проект). Имена: `1.png`, `36a.png`, `104.png` или с суффиксом Cloudinary `98_gel9bi.png`.
- **images/** — все медиа для карточек. Имена: `9a.jpg`, `9b.jpg`, `104a.jpg`, `104b.JPG`, `36a.png`, `36b.png` и т.д. Число = номер проекта, буква = порядок (25a, 25b, 25c).

## Формат portfolio_data.json после загрузки

В JSON — **одна запись на каждый медиафайл** (не на проект). Пример для проекта 36 с четырьмя медиа (36a, 36b, 36c, 36d):

```json
{ "id": "36a", "media": { "filename": "36a.png", "type": "image", "path": "https://res.cloudinary.com/ВАШ_КОНТЕЙНЕР/image/upload/images/36a", "thumbnail": "https://res.cloudinary.com/ВАШ_КОНТЕЙНЕР/image/upload/icons/36a" }, "title": "Название проекта", "description": "...", "additional": { "col_2": "Тег", ... } },
{ "id": "36b", "media": { "filename": "36b.png", "type": "image", "path": "https://.../images/36b", "thumbnail": "https://.../icons/36b" }, ... },
{ "id": "36c", "media": { ... } },
{ "id": "36d", "media": { ... } }
```

- **id** — строка `"25a"`, `"104b"` или число `25` (если один медиа в проекте). Число в id = номер проекта, буква = порядок показа в карточке (по алфавиту: 25a, 25b, 25c).
- **media.path** — полный URL медиа на Cloudinary (папка images).
- **media.thumbnail** — URL иконки на Cloudinary (папка icons). Для иконки на доске берётся thumbnail **первого** медиа проекта (по порядку a, b, c…).
- **title**, **description** — можно задать один раз для первого медиа проекта; в карточке показывается заголовок и описание проекта (от первого элемента).

Код группирует записи по числу из id (25a, 25b, 25c → проект 25), сортирует по букве и показывает одну иконку на проект, в карточке — все медиа по порядку с прокруткой.

## Файл cloudinary_mapping.json (опционально)

Если на Cloudinary у файлов есть суффиксы (например `98_gel9bi`), создайте в корне проекта файл `cloudinary_mapping.json`:

```json
{
  "images": { "98": "98_gel9bi", "9a": "9a_abc12" },
  "icons": { "98": "98_gel9bi", "9": "9_xyz" }
}
```

- **images** — соответствие логического id медиа (из имени файла) и public_id на Cloudinary.
- **icons** — то же для иконок (по номеру проекта).

Public_id можно взять из URL в медиабиблиотеке Cloudinary (часть после последнего `/` до расширения, например `98_gel9bi`). После создания маппинга запустите снова `python build_portfolio_from_folders.py`.

## Перенос тегов и названий из таблицы

Структура таблицы **сайт_портфолио.xlsx**:

| Колонка 1 | Колонка 2 | Колонка 3 | Колонка 4 | Колонка 5 |
|-----------|-----------|-----------|-----------|-----------|
| Номер проекта | Название проекта | Описание проекта | Тег 1 | Тег 2 |

1. Положите таблицу **сайт_портфолио.xlsx** в корень проекта.
2. Запустите: `python merge_table_into_portfolio.py`

Скрипт найдёт строку по номеру проекта в первой колонке и заполнит у всех записей этого проекта (2, 3a, 3b, …) поле **title** из кол.2, **description** из кол.3, теги для сайдбара из кол.4–5. На сайте появятся названия, описания и теги.
